

# Fix Login Issues After Migrating Back to Supabase

## Problem Analysis

There are **3 root causes** preventing login from working:

### 1. Wrong Supabase Instance (CRITICAL)
The `.env.production` and `.env.development` files point to an old external Supabase project (`tobclczszdikmgvkvngf`), but the Lovable Cloud project is `xrnnsysvwbbulezhvszb`. The client uses `VITE_SUPABASE_ANON_KEY` which reads from the wrong env var — the auto-generated `.env` has `VITE_SUPABASE_PUBLISHABLE_KEY` set correctly but `VITE_SUPABASE_ANON_KEY` is empty.

**Fix**: Delete `.env.production` and `.env.development` (they override the auto-generated `.env`). Update `client.ts` to use `VITE_SUPABASE_PUBLISHABLE_KEY` instead of `VITE_SUPABASE_ANON_KEY`. *Note: I cannot edit `client.ts` directly since it's auto-generated, but the `.env` files are the real culprit — removing the overrides will let the correct Cloud values take effect.*

### 2. Profile fetch crashes dashboard (RUNTIME ERROR)
After login, `StudentDashboard` accesses `profile.id` but `profile` can be null (the `profiles` table query fails because it's hitting the wrong Supabase). Even after fixing the Supabase connection, we need a null guard.

**Fix**: Add `if (!profile) return <Loading />` guard in `StudentDashboard.tsx`.

### 3. Types mismatch with Cloud database
The local `types.ts` references tables/columns that don't exist in the Cloud database (`student_levels`, `recommendations`, `gallery_events`, `gallery_media`, and profile columns like `gpa`, `interests`, `extracurriculars`). This causes runtime failures when querying.

**Fix**: The auto-generated `types.ts` will be updated automatically once we're connected to the right Supabase. No manual action needed.

### 4. Build error in Recommendations.tsx
Missing closing `}` brace for the component function.

**Fix**: Add the missing closing brace before the export.

## Implementation Steps

1. **Delete `.env.production` and `.env.development`** — These override the auto-generated `.env` and point to the wrong Supabase instance. Removing them ensures the app uses the correct Lovable Cloud credentials.

2. **Fix `Recommendations.tsx` build error** — Add missing `};` closing brace before the export statement (around line 360).

3. **Add null guard in `StudentDashboard.tsx`** — Return a loading state when `profile` is null instead of crashing.

4. **Add null guard in other dashboards** — Check `ParentDashboard`, `TeacherDashboard`, `SchoolAdminDashboard` for similar `profile.id` access without null checks.

## Technical Details

- The `.env` file (auto-generated by Lovable Cloud) has the correct `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` pointing to `xrnnsysvwbbulezhvszb`
- Vite loads `.env.development` / `.env.production` with higher priority than `.env`, so the old external values were overriding the correct ones
- The `client.ts` file reads `VITE_SUPABASE_ANON_KEY` but the Cloud `.env` only sets `VITE_SUPABASE_PUBLISHABLE_KEY` — however, `client.ts` is auto-generated and will be corrected once the override files are removed
- Auth signup already succeeded on the old Supabase — the user may need to re-register on the Lovable Cloud instance
